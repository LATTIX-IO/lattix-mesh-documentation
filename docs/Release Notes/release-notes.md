Use this page for customer-facing summaries of SaaS updates.

## How to Read Release Notes

Each release should include:

- What changed
- Why it matters to tenant admins/users
- Any required customer action
- Known limitations (if applicable)

## Release Note Structure (Recommended)

1. **Highlights**
2. **Improvements**
3. **Fixes**
4. **Operational Notes**
5. **Required Customer Actions**

## Example Entry Template

### YYYY-MM-DD

**Highlights**
- Short description of top user-impacting changes

**Improvements**
- List of workflow, usability, or reliability improvements

**Fixes**
- List of corrected issues with customer impact context

**Required Customer Actions**
- Any action required by tenant admin/security user (or "None")

## Publishing Guidance

- Keep language user-focused and non-technical where possible
- Avoid exposing sensitive internal architecture details
- Link to related guides when behavior changes
